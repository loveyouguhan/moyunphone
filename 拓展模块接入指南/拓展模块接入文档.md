# 墨韵手机拓展模块制作指南

本文适用于墨韵手机的动态应用模块。模块以单个 `module.js` 文件导入，文件内部同时包含 manifest 元数据和模块代码。模块代码会在当前 SillyTavern 页面中执行，因此这是“受信任代码”机制，不是安全沙箱。只导入你自己编写或明确信任的模块。

## 1. 模块文件

当前导入器只接受一个文件：

```text
my-module.js
```

`module.js` 是自描述的单文件 ES Module，必须同时导出：

- `manifest`：模块元数据和权限声明。
- 默认导出工厂函数，或命名导出 `createModule`：模块运行入口。

文件名不要求固定为 `module.js`，可以使用任意 `.js` 或 `.mjs` 文件名；推荐发布为 `my-module.js`。manifest 的 `entry` 推荐填写 `self`，表示入口就是当前文件。

`my-module.js` 不能依赖浏览器里不存在的 npm 包，也不要在运行时从远程 URL 加载脚本。图片可以直接写成 `data:image/...`，或使用 HTTPS 图片地址。建议作者发布压缩包时保留源代码、版本号、权限清单、文件校验值和源码地址，但用户导入的入口始终是单个 `.js/.mjs` 文件。

## 2. module.js 中的 manifest

manifest 必须作为 `module.js` 的命名导出提供，不能再单独放在 `manifest.json` 中：

```js
export const manifest = {
  protocolVersion: 1,
  id: 'daily-note',
  name: '每日便签',
  version: '1.0.0',
  author: '作者名',
  description: '记录当前聊天中的每日小目标',
  icon: 'data:image/svg+xml,%3Csvg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 64 64"%3E%3Crect width="64" height="64" rx="16" fill="%233e6fdb"/%3E%3C/svg%3E',
  entry: 'self',
  permissions: ['moduleStorage'],
};
```

字段要求：

| 字段 | 要求 |
| --- | --- |
| `protocolVersion` | 当前必须为 `1`。 |
| `id` | 2–64 个字符，只能使用小写字母、数字、`.`、`_`、`-`，且首字符必须是小写字母。发布后不要复用旧 ID。 |
| `name` | 首页显示名称，不能为空，最多 40 个字符。 |
| `version` | 建议使用语义化版本，例如 `1.2.0`。最多 32 个字符。 |
| `author` | 作者或团队名，最多 80 个字符。 |
| `description` | 可选说明，最多 400 个字符。 |
| `icon` | 可选的 `data:image/*` 或 HTTPS 图片地址。不要使用 HTTP、SVG 外链脚本或超大图片。 |
| `entry` | 推荐填写 `self`，表示入口就是当前导入的单文件；也可以填写该 `.js/.mjs` 文件名。 |
| `permissions` | 只声明实际使用的能力；未声明的能力会在运行时拒绝。 |
| `api` | 可选的生成 API 绑定方式，见第 6 节。 |

支持的权限：

- `generation`：调用统一生成、配置库配置或模块独立 API。
- `image`：调用手机当前生图配置。
- `worldBook`：读取经过截断和筛选的世界书快照。
- `phone.read`：按应用读取通用的联系人、会话、消息和动态快照。
- `wechat.read` / `wechat.write`：读取微信会话，发送微信消息，或分享内容到聊天/朋友圈。
- `calendar.read` / `calendar.write`：读取、添加、更新、删除剧情日历事件。
- `pxx.read` / `pxx.write`：读取、添加或生成 PXX 商品。
- `memory.read` / `memory.write`：列出、读取、检索记忆，或整理楼层、合并总结。
- `vector.read` / `vector.write`：向量检索或重建索引。
- `variables.read` / `variables.write`：读取聊天/指定楼层变量，或按路径更新变量。
- `database.read`：读取数据库表快照或指定表；不开放任意 SQL。
- `database.write`：通过受控的行级接口更新、新增和删除表格行。
- `floorTriggers`：读取正文楼层，并注册“每 X 个楼层”自动触发器。
- `moduleStorage`：保存模块自己的持久化数据。

不要为了“以后可能用到”而申请全部权限。用户在导入管理页可以看到模块权限，过度申请会降低可信度。

## 3. module.js 入口

入口默认导出一个工厂函数，也可以命名导出 `createModule`。工厂收到一个 Host API，并返回模块定义：

```js
export default function createModule(api) {
  return {
    manifest: api.module.manifest,
    render(host) {
      const page = document.createElement('section');
      page.className = 'my-module-page';

      const title = document.createElement('h2');
      title.textContent = '每日便签';
      const input = document.createElement('textarea');
      input.placeholder = '今天想完成什么？';
      const save = document.createElement('button');
      save.type = 'button';
      save.textContent = '保存';
      const result = document.createElement('p');

      save.addEventListener('click', async () => {
        const value = input.value.trim();
        await host.storage.set('note', value);
        result.textContent = value ? '已保存。' : '已清空。';
      });

      page.append(title, input, save, result);
      return page;
    },
    dispose() {
      // 清理模块自己创建的定时器、订阅和全局监听器。
    },
  };
}
```

实际模块页面由插件放入手机 Shadow DOM 内。模块应使用 `textContent`、`createElement` 和事件监听器构建页面，不要把用户内容或模型内容拼到 `innerHTML` 中。

`render` 每次打开应用时可能被重新调用。不要依赖上一次 DOM 节点仍然存在；需要保留的数据写入 `host.storage`，需要清理的资源在 `dispose` 中处理。

## 4. Host API 总览

模块只能通过工厂收到的 `api` 访问插件能力：

```js
api.module
api.state
api.time
api.generation
api.apps
api.wechat
api.calendar
api.pxx
api.image
api.worldBook
api.memory
api.vector
api.variables
api.database
api.floors
api.notify
api.modal
api.storage
api.api
```

模块不能依赖插件内部私有字段、`PhoneRuntime`、`PhoneStore`、`window.SillyTavern` 或 `window.AutoCardUpdaterAPI`。内部文件名和私有方法可能随版本改变，公开 Host API 才是兼容边界。

### 4.1 模块信息和配置

```js
const moduleId = api.module.id;
const manifest = api.module.manifest;
const currentSettings = api.module.settings;

await api.module.updateSettings({
  showArchived: true,
  pageSize: 20,
});
```

模块设置是插件级配置，不要把聊天剧情内容放进去。模块设置上限为 64KB，建议只保存开关、筛选条件和用户偏好。

### 4.2 模块存储

声明 `moduleStorage` 后，可以使用按模块、按聊天作用域隔离的存储：

```js
const lastNote = await api.storage.get('note');
await api.storage.set('note', { text: '今天完成了跑步', updatedAt: Date.now() });
await api.storage.remove('note');
await api.storage.clear();
```

存储键只能使用字母、数字、`.`、`_`、`-`，单次值不能超过 256KB。数据在当前聊天作用域下保存；切换聊天后不会读到另一个聊天的数据。删除模块时模块数据会一并清理，因此不要把用户需要长期备份的资料只放在这里。

### 4.3 统一生成

统一生成适合依赖手机当前世界观、世界书、当前剧情和统一生成配置的功能。manifest 声明：

```json
{
  "api": { "mode": "shared" },
  "permissions": ["generation"]
}
```

调用方式：

```js
const text = await api.generation.generate({
  system: '你是一个简洁的任务整理器。只输出任务列表。',
  user: '请把下面内容整理成最多 5 项任务：\n' + sourceText,
  maxTokens: 500,
});
```

统一生成沿用手机当前生成 provider、主/副 API、温度、最大 token、重试和酒馆回退设置。模块负责业务提示词，插件负责调用通道和基础边界。不要在 system prompt 中要求模型输出 HTML；对结构化结果使用 `generateJson` 并在代码中校验：

```js
const result = await api.generation.generateJson({
  system: '只输出 JSON，不要 Markdown。字段为 items: string[]。',
  user: `整理内容：${sourceText}`,
  validate(value) {
    return Boolean(
      value && typeof value === 'object' &&
      Array.isArray(value.items) &&
      value.items.every((item) => typeof item === 'string'),
    );
  },
});
```

如果你的模块像微信一样先累计多条消息，再统一生成下一条回复，请使用 `reply`。`waitFor` 表示本次最多携带最后 X 条消息，范围 1–40，默认 20；它不会自行等待计时，也不会把结果自动写入某个应用：

```js
const reply = await api.generation.reply({
  waitFor: 8,
  messages: [
    { role: 'system', content: '你是游戏中的旅店老板，回复简短自然。' },
    { role: 'user', content: '今晚还有房间吗？' },
    { role: 'assistant', content: '楼上还剩一间。' },
    { role: 'user', content: '能看到港口吗？' },
  ],
  temperature: 0.8,
  maxTokens: 300,
});
```

`messages` 按时间升序填写，角色只能是 `system`、`user`、`assistant`。Host 会截断单条超长内容、只保留最后 X 条，并像微信统一回复一样补充当前剧情时间、联系人、会话、可用世界书摘录和最近正文，然后通过统一生成通道调用模型。若要把回复写入微信，请由用户确认后再调用 `api.wechat.send(...)`；不要在页面打开时自动替用户发送。

推荐提示词结构：

1. 明确角色和业务目标。
2. 明确输入字段，不要让模型猜测不存在的 ID。
3. 明确输出格式和最大数量。
4. 明确“只输出 JSON，不输出解释、Markdown、代码围栏”。
5. 对模型输出再次做长度、类型、枚举和 ID 校验。
6. 失败时显示通知或使用本地回退，不要把原始模型文本直接当作界面代码。

### 4.4 模块独立 API

模块可以不使用统一生成，而使用自己的配置。支持两种方式。

复用 API 配置库中的命名配置。模块只声明需要“配置库选择”能力，不在 manifest 中写死配置名称：

```js
export const manifest = {
  // 其他元数据省略
  api: { mode: 'profile' },
  permissions: ['generation', 'moduleStorage'],
};
```

Host 会把已保存配置的脱敏列表暴露给模块：

```js
const profiles = api.api.profiles;
// [{ name: '便宜模型', model: 'example-model', baseUrl: 'https://...' }]
```

模块应在自己的设置区域渲染下拉列表，用户选择后保存选择结果：

```js
await api.module.updateSettings({
  apiProfileName: selectedProfileName,
});
```

`api.api.binding` 是当前解析后的绑定信息：当模块声明 `profile` 但尚未选择配置时，`mode` 仍为 `profile`，而 `profileName` 为空。此时模块可以继续提供本地功能，但调用 `api.generation` 会因缺少配置而失败；页面应明确提示用户选择配置，而不是自动回退到统一生成。配置库名称被删除或改名后也要按同样方式处理，不能静默使用其他配置。

生成请求会优先使用模块设置中的 `apiProfileName`，再回退到 manifest 中的 `profileName`（适合迁移旧模块）。如果两者都没有选择，调用生成时会失败并显示配置缺失提示。模块不能读取配置库中的 API Key；真正的完整配置解析和请求发送由 Host 完成。

使用模块包内的独立配置：

```json
{
  "api": {
    "mode": "custom",
    "config": {
      "enabled": true,
      "baseUrl": "https://api.example.com/v1",
      "apiKey": "在这里填写用户自己的密钥",
      "model": "example-model",
      "temperature": 0.7,
      "maxTokens": 1200,
      "maxContextTokens": null,
      "retryCount": 3,
      "stream": true
    }
  },
  "permissions": ["generation"]
}
```

不要在公开模块包中写入作者自己的真实 API Key。`custom` 配置应由用户自行修改模块配置或由后续设置界面提供；密钥不应写入作者发布的代码、截图、日志或错误消息。

### 4.5 API 配置库如何获取和选择

1. 打开手机首页。
2. 进入“设置”。
3. 打开“API 配置”。
4. 在“API 配置库”中创建并保存一个或多个命名配置。
5. 导入模块后，打开模块自己的“生成配置”下拉列表。
6. 选择已保存的配置；模块只保存配置名称，不保存 API Key。
7. 如果配置库新增、删除或修改了配置，重新打开模块即可刷新列表。

配置库名称大小写和空格会原样显示，但模块应使用列表项的 `name` 保存，不要让用户手动输入配置名。模块如果需要默认选择，可以在自己的设置中保存 `apiProfileName`，但发布包不要写入作者指定的真实配置名称。

常见错误：

- Base URL 不要重复填写 `/chat/completions`；一般填写服务的 `/v1` 根地址。
- API 能连接但没有模型时，检查服务是否支持 `/models` 或酒馆后端代理是否可用。
- 配置库名称大小写和空格必须与 `profileName` 匹配。
- 模块只会收到脱敏后的配置列表展示信息，不能读取配置库全部密钥；真正发请求由插件 Host API 完成。

### 4.6 世界书

声明 `worldBook` 后读取已经经过插件筛选、字符上限和安全截断的快照：

```js
const world = api.worldBook.snapshot();
if (world.available) {
  const promptContext = world.excerpt;
}
```

返回内容包括 `available`、已绑定的 `books`、条目 `names` 和 `excerpt`。它是只读快照，不保证每个聊天都有世界书。不要直接读取宿主的世界书对象，也不要把完整世界书无上限塞入提示词。

### 4.7 记忆库和向量库

记忆库检索与维护：

```js
const items = api.memory.list({ includeArchived: false, kind: 'summary', limit: 50 });
const memory = api.memory.get(12); // 按记忆编号
const sameMemory = memory ? api.memory.get(memory.id) : null; // 也可按 ID
const hits = await api.memory.search('用户最近答应的约定');
for (const hit of hits) {
  console.log(hit.id, hit.content);
}

await api.memory.memorize();
await api.memory.consolidate();
```

向量库接口：

```js
const hits = await api.vector.search('与当前页面相关的记忆');
await api.vector.rebuild();
```

`memory.read`、`memory.write`、`vector.read`、`vector.write` 分开申请。普通展示模块只申请读权限；不要在页面打开时自动重建索引或自动整理大量楼层。记忆操作可能调用模型并消耗 API 额度，应该由用户点击按钮触发并显示处理中状态。

### 4.8 变量

```js
const latestFloor = await api.variables.read();
const floor12 = await api.variables.read({ scope: 'message', messageId: 12 });
const chatVariables = await api.variables.read({ scope: 'chat' });
const compact = await api.variables.read({ compact: true });

if (latestFloor.available) {
  const outcome = await api.variables.update('stat_data.todoCount', 3);
  if (!outcome.ok) api.notify(outcome.message, 'error');
}
```

`read` 始终返回完整状态对象：`available`、`reason`、`scope`、`messageId`、`lastMessageId`、`source`、`data`。`compact: true` 会折叠 MVU 二元组并限制体积，适合放入提示词；编辑页面需要保留 MVU 描述时不要开启。`update` 默认写最新楼层，也可传 `{ scope: 'chat' }` 或指定 `messageId`。

### 4.9 图片、数据库、通知和弹窗

```js
const imageUrl = await api.image.generate('a clean blue notebook icon');
api.notify('图片生成完成。', 'success');

const values = await api.modal('编辑内容', [
  { name: 'title', label: '标题', required: true },
]);
```

图片能力使用手机当前生图配置，因此需要声明 `image`。数据库当前只开放受控的表/快照读取：

```js
const tables = await api.database.query({ kind: 'tables' });
const rows = await api.database.query({ kind: 'table', tableName: 'some_table', limit: 50 });
```

不要执行任意 SQL、修改系统表或把数据库结果直接拼接进 HTML。数据库插件不可用时，调用会返回不可用状态或失败结果，模块应提供空状态和重试按钮。

完整表快照和受控行级写入：

```js
const snapshot = await api.database.tables();
if (snapshot.available) {
  const inserted = await api.database.insertRow('任务表', {
    标题: '确认船票',
    状态: '待办',
  });
  if (inserted.rowIndex) {
    await api.database.updateRow('任务表', inserted.rowIndex, { 状态: '完成' });
    await api.database.deleteRow('任务表', inserted.rowIndex);
  }
}
```

写接口分别需要 `database.write`，`rowIndex` 是从 1 开始的数据行号，不包含表头。所有写操作都返回 `{ ok, message }`，新增行成功时还会返回 `rowIndex`。不要把模型输出未经字段白名单校验就写入数据库。

### 4.10 手机时间

`api.time` 使用手机当前聊天作用域的**剧情时间**，不是创作者设备的系统时间。它会跟随剧情时钟、变量绑定以及手机操作推进：

```js
const timestamp = api.time.now();
const date = api.time.date();
const label = api.time.format();
const shortTime = api.time.format({ hour: '2-digit', minute: '2-digit' });
```

`now()` 返回毫秒时间戳，`date()` 返回新的 `Date` 对象，`format(options?, locale?)` 默认使用 `zh-CN` 的中等日期和短时间格式。

### 4.11 读取其他应用

声明 `phone.read` 后可读取任一社交应用的统一快照：

```js
const appIds = api.apps.list(); // wechat / forum / anonymous / twitter
const forum = api.apps.snapshot('forum');
console.log(forum.profiles, forum.conversations, forum.messages, forum.posts);
```

返回值只包含所选应用关联的数据。专用业务优先使用下列 `wechat`、`calendar`、`pxx` 接口；`state.snapshot()` 是旧版兼容的全手机状态快照，不应作为新模块的数据耦合入口。

### 4.12 微信聊天与分享

读取微信需要 `wechat.read`，发送或分享需要 `wechat.write`：

```js
const contacts = api.wechat.profiles();
const conversations = api.wechat.conversations();
const conversation = conversations[0];
if (conversation) {
  const history = api.wechat.messages(conversation.id, 30);
  await api.wechat.send(conversation.id, '这是模块发送的一条消息');

  await api.wechat.share({
    conversationId: conversation.id,
    content: '分享：今天的行程已经整理好',
    metadata: { sourceModule: api.module.id },
  });
}
```

不提供 `conversationId` 时，`share` 会发布到朋友圈，并进入统一待生成队列：

```js
await api.wechat.share({ content: '分享一张今天拍到的晚霞。' });
```

发送聊天消息和发布朋友圈都会推进剧情时间，并像微信原生操作一样进入待处理队列。模块不应静默替用户发送；应显示目标会话和内容预览，并由按钮确认。

### 4.13 日历

```js
const events = api.calendar.list();
const today = api.calendar.get('2026-08-19');
await api.calendar.upsert('2026-08-20', '港口祭', '晚上在旧港举行庆典。');
await api.calendar.remove('2026-08-20');
```

读取需要 `calendar.read`，修改需要 `calendar.write`。日期必须为 `YYYY-MM-DD`。同一天只有一个事件，`upsert` 会覆盖该日期的旧事件；事件到达当天后会进入手机生成上下文。

### 4.14 PXX

```js
const products = api.pxx.list();
await api.pxx.add([{
  name: '便携式星图灯',
  price: '¥39.9',
  description: '适合露营的小型投影灯。',
  category: '家居',
}]);

const generated = await api.pxx.generate({ count: 6 });
const saved = await api.pxx.add(generated);
```

读取需要 `pxx.read`，添加与生成需要 `pxx.write`；`generate` 还需要 `generation`，只返回候选商品，不会自动保存。这样作者可以先展示预览、让用户删除不合适的候选，再调用 `add`。

### 4.15 楼层读取与自动触发

声明 `floorTriggers` 后，可以读取正文并注册自动触发器：

```js
const latestFloor = api.floors.latest();
const recent = api.floors.recent(12);

const stop = api.floors.onTrigger(
  {
    role: 'assistant',
    every: 5,
    afterFloor: 0,
    runOnRegister: false,
  },
  async (floor) => {
    const result = await api.generation.reply({
      waitFor: 10,
      messages: api.floors.recent(10).map((item) => ({
        role: item.role,
        content: `${item.name}：${item.text}`,
      })),
      maxTokens: 300,
    });
    await api.storage.set('latest-auto-result', {
      floor: floor.floor,
      result,
      createdAt: api.time.now(),
    });
  },
);
```

`role` 可选 `assistant`、`user`、`any`，默认 `assistant`；`every` 为每多少个**符合角色的新楼层**触发一次，范围 1–1000；`afterFloor` 之前的楼层忽略。重复收到同一楼层事件不会重复触发。`runOnRegister` 默认关闭，开启时会立刻检查当前最新楼层。

`onTrigger` 返回注销函数，模块必须在 `dispose` 中调用。切换聊天、停用或删除模块时 Host 也会清除注册，避免跨聊天误触发。自动回调可能调用模型并消耗额度，模块必须提供显式开关、执行频率和最近执行记录；不要默认开启高频生成。

## 5. 页面和生命周期规范

- 不要修改手机壳外部 DOM、宿主页面 DOM、全局 CSS 或全局变量。
- 使用 `textContent`，不要使用 `innerHTML` 处理用户文本、世界书文本、记忆文本和模型结果。
- 每一个 `addEventListener`、`setInterval`、`setTimeout`、Observer、AbortController 都要能在 `dispose` 中清理。
- 页面操作应禁用重复点击，使用 `try/finally` 恢复按钮状态。
- API 错误只显示经过截断和脱敏的错误，不显示完整 Key、Authorization 头或完整请求体。
- 不要请求远程 JavaScript、不要 `eval`、不要 `new Function`、不要把聊天内容上传到作者自己的服务器。
- 模块代码上限约 1.5MB，图标上限约 512KB；应自行压缩 bundle 和图片。
- 模块异常会被手机容器捕获，但异常模块可能被启动时自动停用；发布前必须在空聊天、无 API、无世界书和记忆库关闭时测试。

## 6. 推荐制作流程

1. 先写不调用 API 的纯本地页面，确认导入、显示和删除正常。
2. 增加 `moduleStorage`，验证切换聊天后数据隔离。
3. 按最小权限增加统一生成或配置库 API。
4. 为每次模型调用编写输入截断、输出校验和失败回退。
5. 最后再增加世界书、记忆、变量或数据库能力。
6. 更新版本号、权限说明、源代码地址和变更记录。
7. 用全新聊天导入测试，并确认删除模块后的数据清理行为。

发布检查清单：

- [ ] 模块 manifest 的 `id` 唯一且 `protocolVersion` 正确。
- [ ] 单文件 `.js/.mjs` 同时包含 manifest 和入口工厂，默认导出工厂函数或 `createModule`。
- [ ] 没有真实 API Key、远程脚本、隐式网络上传或任意 SQL。
- [ ] 权限列表只包含实际使用的能力。
- [ ] 所有用户/模型文本使用 DOM 文本节点渲染。
- [ ] 所有定时器、事件监听器和订阅都有清理逻辑。
- [ ] 无 API、无世界书、无记忆数据时仍有可用空状态。
- [ ] 统一生成和独立 API 两种策略的说明已写给用户。
- [ ] 已测试导入、启用、停用、打开、聊天切换和删除。

## 7. 完整示例：使用 API 配置库的备忘录

仓库中的 `examples/memo-notebook/module.js` 是一个可直接导入的单文件示例。它与导入器的真实契约一致：文件同时导出 `manifest` 和默认工厂函数，导入时不需要旁边的 `manifest.json` 或其他资源文件。

```text
examples/memo-notebook/
└─ module.js
```

它实现了以下功能：

- 在 `moduleStorage` 中保存当前聊天的备忘录，支持新建、编辑、搜索、置顶、归档和删除。
- 使用 `generation` 权限，在用户点击“AI 整理草稿”后调用模型。
- 通过 `generateJson` 要求模型返回标题、正文、标签和优先级，并在客户端校验类型、长度和枚举值。
- 在模块页面列出脱敏后的 API 配置库条目，用户选择后只保存配置名称，不保存 API Key。
- 所有用户内容和模型结果都通过 `textContent` 或表单 `value` 写入 DOM，不使用 `innerHTML`。
- API 不可用、配置不存在或模型返回非法结果时，保留本地编辑内容并显示脱敏后的错误通知。

### 7.1 配置库准备

示例 manifest 只绑定 API 配置库模式，不绑定作者指定的配置名称：

```js
export const manifest = {
  // 其他元数据省略
  api: { mode: 'profile' },
  permissions: ['generation', 'moduleStorage'],
};
```

导入前在“设置 → API 配置 → API 配置库”新建并保存一个配置，至少填写 Base URL、API Key 和模型。导入示例后，在备忘录页面的“生成配置”下拉框中选择它。模块保存的是配置名称，名称大小写和空格必须与配置库条目完全一致。

模块运行时不会读取或暴露 API Key。Host 通过 `api.api.profiles` 向模块提供 `name`、`model`、`baseUrl` 脱敏列表，并通过模块设置中的 `apiProfileName` 解析真正的请求配置。如果当前选中的配置被删除或改名，页面会显示缺失状态；重新选择有效配置后才能调用 AI 整理。配置库为空时，本地备忘录 CRUD 仍然可用。

### 7.2 数据模型和存储策略

示例把所有备忘录放在存储键 `notes` 下，实际值是一个带版本号的对象：

```json
{
  "version": 1,
  "notes": [
    {
      "id": "memo-唯一值",
      "title": "准备周末旅行",
      "body": "周五确认车票，周六带充电宝。",
      "tags": ["旅行"],
      "priority": "normal",
      "pinned": false,
      "archived": false,
      "createdAt": 1760000000000,
      "updatedAt": 1760000000000
    }
  ]
}
```

`api.storage` 已按模块 ID 和当前聊天作用域隔离，因此模块只需要保存自己的键，不要自行拼接聊天 ID。读取旧数据时要做类型归一化；保存时限制条目数、标题长度、正文长度和标签长度，避免单次值超过 Host 的 256KB 限制。删除模块时 Host 会清理该模块的数据，所以需要长期备份的内容应提供导出功能或另存到用户可控位置。

### 7.3 专用提示词和结构化输出

提示词属于模块业务逻辑，不放在 manifest 的 API 配置中。示例使用固定的 system prompt，要求模型：

1. 保留原文中的人名、日期、数字、专有名词和不确定性。
2. 不凭空补充事实，不生成 HTML、Markdown 或代码围栏。
3. 只输出 `title`、`body`、`tags`、`priority` 四个字段。
4. 限制标题、正文、标签数量和优先级枚举。

调用模式如下：

```js
const result = await api.generation.generateJson({
  system: MEMO_SYSTEM_PROMPT,
  user: buildMemoUserPrompt(title, tags, draft),
  temperature: 0.2,
  maxTokens: 900,
  validate(value) {
    return isMemoDraft(value);
  },
});
```

`validate` 不是可选的装饰代码，而是模型输出进入业务状态前的边界。校验失败时不要尝试把原始文本当作备忘录正文；应保留用户草稿、显示错误，并允许用户本地保存。提示词中的输入也要截断，避免用户粘贴超长聊天内容导致模型请求失控。

### 7.4 生命周期和重渲染

`render` 可能在每次打开模块时重新调用。示例将数据放在 `api.storage`，将当前页面节点放在工厂闭包中；重新渲染时重建列表，不依赖旧 DOM。模块只创建页面内的 `<style>` 和事件监听器，`dispose` 将引用置空并阻止异步读取完成后再次刷新页面。

如果模块增加了窗口级监听器、定时器、Observer 或请求取消器，应把它们集中登记，并在 `dispose` 中逐一清理。页面内按钮的异步操作必须在 `try/finally` 中恢复禁用状态，防止用户重复提交 API 请求。

## 8. 模块验证矩阵

发布前至少执行以下测试：

1. API 配置库存在且模型可用：本地保存、AI 整理、编辑后保存都成功。
2. API 配置库不存在：本地 CRUD 仍可用，AI 操作只显示错误，不丢失草稿。
3. 模型返回 Markdown、缺字段、错误枚举或超长字段：校验失败，不写入模型结果。
4. 切换到另一个聊天：看不到前一个聊天的备忘录；切回后数据恢复。
5. 停用、重新启用和删除模块：页面生命周期正常，删除后模块数据被清理。
6. 空聊天、无世界书、无记忆库：模块仍能使用本地功能。
7. 移动端窄屏：搜索、编辑器和操作按钮不溢出手机页面。

如果模块使用了独立 `custom` API，应额外确认导入管理页和模块页面都不会显示完整密钥，并确认发布包中没有真实密钥。
