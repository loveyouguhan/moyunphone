# 模型输出协议

手机有两套模型输出协议：统一回复批次使用 `generation`，正文自动解析使用 `autoParse`。两者都要求模型只返回一个 JSON 对象。
运行时可用 `api.meta.protocols()` 取到同一份版本号、限制、动作字段与 JSON Schema。

## generation（v1）

统一回复批次的 JSON 动作协议，包含动作、批次标识和可选变量更新。

动作类型：`message.reply`、`moment.create`、`forum.thread.create`、`forum.ambient.create`、`forum.reply.create`、`twitter.post.create`、`twitter.ambient.create`、`twitter.reply.create`、`twitter.repost.create`、`interaction.like`、`interaction.comment`、`message.claim`

限制：`maxActions=40`、`maxVariableUpdates=10`、`maxActorNameLength=24`、`maxThoughtLength=400`、`maxCommonContentLength=500`、`maxLongContentLength=1200`、`maxTitleLength=80`、`maxVariablePathLength=200`、`maxDelayMinutes=45`

| 动作 | 必填 | 可选 | 约束 |
| --- | --- | --- | --- |
| `message.reply` | `type`、`content`、`actorProfileId`、`conversationId` | `thought`、`delayMinutes` | 已有角色在本批次允许的会话中回复；正文最多 500 字。 |
| `moment.create` | `type`、`content`、`actorProfileId` | `thought`、`delayMinutes` | 微信朋友圈动态；正文最多 500 字。 |
| `forum.thread.create` | `type`、`content`、`actorProfileId` | `title`、`thought`、`delayMinutes` | 论坛主题；title 最多 80 字，正文最多 1,200 字。 |
| `forum.ambient.create` | `type`、`content`、`actorName` | `title` | 论坛路人主题；actorName 最多 24 字，正文最多 1,200 字。 |
| `forum.reply.create` | `type`、`content`、`actorProfileId|actorName`、`parentId|targetId` | `thought`、`delayMinutes` | 论坛回复；目标必须存在，正文最多 1,200 字。 |
| `twitter.post.create` | `type`、`content`、`actorProfileId` | `thought`、`delayMinutes` | Twitter 动态；正文最多 500 字。 |
| `twitter.ambient.create` | `type`、`content`、`actorName` | — | Twitter 路人动态；actorName 最多 24 字，正文最多 500 字。 |
| `twitter.reply.create` | `type`、`content`、`actorProfileId|actorName`、`parentId|targetId` | `thought`、`delayMinutes` | Twitter 回复；目标必须存在，正文最多 500 字。 |
| `twitter.repost.create` | `type`、`content`、`actorProfileId|actorName`、`parentId|targetId` | `thought`、`delayMinutes` | Twitter 转发；目标必须存在，正文最多 500 字。 |
| `interaction.like` | `type`、`content`、`actorProfileId|actorName`、`targetId` | `thought`、`delayMinutes` | 对已有帖子点赞；content 仍需填写简短行为文本。 |
| `interaction.comment` | `type`、`content`、`actorProfileId|actorName`、`targetId` | `thought`、`delayMinutes` | 对已有帖子评论；目标必须存在，正文最多 500 字。 |
| `message.claim` | `type`、`actorProfileId`、`targetId`、`claimStatus` | `content` | 领取或婉拒红包、礼物、转账消息；content 省略时使用宿主默认文案。 |

处理顺序：

1. 先校验 version 与 batchId，再限制动作数量、角色身份、应用门控和目标存在性。
1. 通过校验的动作按输出顺序执行；variableUpdates 独立校验后写入已有变量路径。
1. 截断 JSON 时宿主尝试恢复已经闭合的动作对象，但会在 issues 中标记恢复。

失败行为：

- 单个动作无效时仅丢弃该动作并记录 issue，不影响同批其他有效动作。
- 变量更新无效或超过 10 条时忽略无效项并记录 issue。
- 版本、batchId 或 JSON 根结构无效时不执行动作。

有效示例：

```json

  "batchId": "batch:example",

    },
    {
      "type": "moment.create",
```

## autoParse（v1）

从正文中提取已发生的内置手机行为和启用模块声明的扩展动作。

动作类型：`wechat.message`、`wechat.moment`、`twitter.message`、`twitter.post`、`forum.thread`、`anonymous.message`、`extensionActions`

限制：`maxActions=24`、`maxExtensionActions=24`

处理顺序：

1. 自动解析器先按内置 schema 校验 actions 与 extensionActions。
1. 内置 actions 经过身份、收信人、应用停用和去重检查后写入手机领域事件。
1. 扩展动作按 moduleId 找到启用模块，再依次执行 schema 校验、parse、validate，最后调用 apply。

失败行为：

- 未知 moduleId、schema 不匹配、parse 返回 undefined 或 validate 返回 false 的扩展动作会被忽略并记录 issue。
- 单个扩展 apply 抛错只影响该动作；其他动作继续执行并在结果中返回 issues。
- 内置动作和扩展动作各自最多 24 条，超出部分忽略。

有效示例：

```json
{
  "version": 1,
  "actions": [
    {
      "kind": "wechat.message",
      "actorName": "沈夜",
      "accountName": "小黑",
      "recipient": "user",
      "content": "到了。"
    },
    {
      "kind": "twitter.post",
      "actorName": "林澈",
      "accountName": "@lin",
      "content": "今晚有雨。"
    }
  ],
  "extensionActions": [
    {
      "moduleId": "delivery-tracker",
      "data": {
        "courier": "顺丰",
        "status": "已签收"
      }
    }
  ]
}
```

## 无效输出会怎样

- 版本号或 `batchId` 不匹配：整轮不执行动作，只记录 issue。
- 单个动作字段缺失、内容超长、目标不存在、角色不属于当前聊天：丢弃该动作，其余动作照常执行。
- 输出被截断：宿主会尝试恢复已经闭合的动作对象，并在 issue 中说明恢复条数。
- 文本里的 `image###英文提示词###`（兼容 `[[生图:...]]`）是宿主生图标记，正文之外不要自造标记。
